# LeLamp/OpenClaw 本地AI办公工作终端产品设计方案

版本：v0.1
日期：2026-05-23
适用：产品讨论、立项评审、路演材料、后续 PRD 展开

## 1. 一句话定位

LeLamp/OpenClaw 是一台桌面本地 AI 办公工作终端，集投影、会议理解、文件扫描、桌面代理执行与办公场景感知于一体，通过本地算力、物理隔离、文件白名单、分级权限和可审计执行，为高频会议与重文档岗位提供比纯软件助手更可控的办公闭环。

## 2. 证据结论

关键判断：
- 会议 AI 已经成为 Teams、Zoom 等办公套件的标配，单纯“自动纪要”不能构成差异化。
- AI 录音硬件说明用户愿意为会议记录硬件付费，但云处理、同意和隐私是核心风险。
- 当前仓库已有 OpenClaw 办公代理雏形，覆盖 Skill、任务拆解、workspace 白名单、审计日志、P0 会议/文档/投影/桌面安全动作。
- 投影是硬件落地最大风险之一，当前 MVP 可先用外接显示器作为投影替代输出，完成会议确认和演示闭环；真实光机进入后续硬件验证。
- 安全不是附加模块，而是产品差异化：默认沙箱、显式授权、全权模式可见、动作可回放。

证据索引见 [research-notes.md](research-notes.md)。硬件取舍见 [hardware-comparison.md](hardware-comparison.md)。

## 3. 产品定位

产品形态：
- 桌面本地 AI 工作终端。
- 不是普通聊天软件，不是单一录音笔，不是会议室大屏投影仪。
- 通过实体硬件提供摄像头、麦克风、投影、状态灯、动作表达和本地安全边界。

核心功能组合：
- 智能投影与会议助手。
- OpenClaw 本地工作代理。
- 实体文档采集系统。
- 多模态办公场景感知。
- 全流程安全架构。

前后台角色：
- 前台“小爱同学”：负责唤醒、简短反馈、状态解释、授权确认、结果播报。
- 后台“OpenClaw 任务执行助手”：负责调研、拆解、文档处理、会议总结、桌面动作、审计和输出文件。

## 4. 目标用户

首批目标：
- 中高频会议人群：管理者、项目负责人、产品经理、咨询顾问、销售/客户成功。
- 重文档岗位：法律、咨询、财务、投研、合同管理、HR、行政与运营。
- 需要现场共识的人群：会后行动项确认、客户会议纪要、内部评审、合同条款讨论。

典型痛点：
- 会议后需要回忆决策、责任人和截止时间。
- 文档分散在本机、下载目录、会议材料、纸质文件和截图中。
- 云端会议 AI 对隐私、客户资料、内部材料不够可控。
- 普通聊天助手不能直接进入本地桌面工作流，也缺少可见确认面。
- 纯软件 Agent 权限边界不清，企业难以审计和批准。

## 5. 核心价值

1. 本地算力：会议、OCR、文档处理、任务拆解和权限判断优先本地完成，减少敏感材料外发。
2. 物理隔离：终端作为独立办公设备，默认只访问 workspace 和授权目录，不继承用户电脑全部权限。
3. 多传感器融合：麦克风、摄像头、投影、灯光和动作形成现场协同，这是纯软件助手难以替代的。
4. 可控执行：OpenClaw 不是只会聊天，而是 Skill 化、可拆解、可确认、可审计的办公代理。
5. 现场确认：投影把行动项、决策、授权提示放到桌面/墙面，让参与者当场修正，减少会后误解。

## 6. 四大核心优势

| 优势 | 内容 | 为什么重要 |
| --- | --- | --- |
| 一体化办公闭环 | 从会议、文档、扫描、待办到桌面协同的连续流程 | 解决会议后信息断裂 |
| 办公场景专用 OpenClaw | Skill 注册、任务拆解、多步骤执行、办公工具适配 | 避免退化成通用聊天助手 |
| 分级权限与可控 AI 执行 | sandbox 默认、full_control 显式开启、逐任务确认 | 企业和个人都能理解风险 |
| 数据安全体系 | 文件白名单、审计日志、本地优先、企业策略部署 | 形成硬件终端的信任边界 |

## 7. 五大核心模块

### 7.1 智能投影与会议助手

能力：
- 会议模式开启、录音/转写、说话人/行动项/决策识别。
- 投影会议倒计时、当前议题、待确认决策、行动项、授权提示。
- 会后生成纪要、transcript、邮件草稿、提醒和投影确认卡。

当前仓库基础：
- `P0OfficeService.generate_meeting_followup_package()` 已覆盖纪要、transcript、邮件草稿、提醒和投影确认。
- `ProjectionService` 已支持 confirmation、status card、countdown、action card。

### 7.2 OpenClaw 本地工作代理

能力：
- Skill 体系：每个技能声明权限模式、说明、实现状态和权限备注。
- 任务拆解：会议、文档、扫描、桌面动作等拆成可执行步骤。
- 多步骤执行：先导入/确认材料，再分析，再生成输出，再等待用户确认。
- 沙箱模式：默认只能访问 workspace 和 allowed roots。
- 全权模式：只在用户明确授权后开启，用于 GUI 自动化或高风险桌面控制。
- 日志审查：所有关键动作写入 append-only JSONL audit log。
- 文件白名单：未导入或未在 allowed roots 的文件默认不可读。

当前 Skill 分层：

| Skill | 权限层级 | MVP 状态 | 产品化说明 |
| --- | --- | --- | --- |
| meeting_capture | sandbox | 已实现基础流程 | 会议模式必须显式开启 |
| document_workspace | sandbox | 已实现文本分析/摘要/对比 | 只读 workspace 或授权目录 |
| paper_scan | sandbox | pipeline/占位后端 | 接入 PaddleOCR 后进入真实验证 |
| projection_assistant | sandbox | 已实现 markdown/确认卡 | 首代投影主场景 |
| desktop_safe_actions | sandbox | 已实现 | 打开应用/URL/允许文件、音量、媒体 |
| desktop_operator | full_control | 门禁已实现 | GUI 自动化后续接入 |
| local_file_search | sandbox | 已实现 | 扫描 workspace 和 allowed roots |
| screen_context | sandbox | adapter-ready | 依赖截图工具和 OCR 后端 |
| lelamp_affordance | sandbox | 已实现/adapter-ready | 姿态、状态灯、场景事件 |

### 7.3 实体文档采集系统

能力：
- 拍摄纸质合同、名片、收据、白板。
- 边缘检测、透视校正、阴影移除、OCR、结构提取、语义分析。
- 输出摘要、条款风险、表格、联系人候选或报告素材。

MVP 边界：
- 使用用户导入的图片或摄像头单帧作为输入。
- OCR 后端优先接 PaddleOCR；未接入时只记录 OCR request，不声称完成识别。
- 对法律/合同结论标记为“AI 辅助初筛，需要人工复核”。

### 7.4 多模态办公场景感知

能力：
- 识别用户靠近、会议可能开始、桌面出现纸张、投影被遮挡、环境光不足。
- 用动作和灯光表达状态：listening、thinking、blocked、success、meeting、projecting。
- 把场景事件送入 OpenClaw，例如“看到纸质合同”后建议扫描。

MVP 边界：
- 单帧观察优先，连续检测作为 sidecar 后续接入。
- 事件推理只作为建议，不自动读取或上传内容。

### 7.5 全流程安全架构

默认访问：
- 本地 workspace。
- 用户显式配置的 `OPENCLAW_ALLOWED_ROOTS`。
- 投影输出目录、审计日志目录、用户批准的本地 memory。

默认禁止：
- 任意全盘扫描。
- 静默读取桌面、浏览器 cookie、邮箱、云盘、聊天记录。
- 自动发送邮件、删除文件、购买、支付、提交表单、拨打电话。
- 未经提示录音或在会议模式外持续转写。

授权方式：
- 文件：导入到 workspace 或加入 allowed roots。
- 会议：用户显式开启会议模式，终端显示录音/会议状态。
- 桌面安全动作：默认 `audit_only`，开启本地执行需设置策略或 UI 开关。
- 全权模式：需要用户在设备 UI/管理后台开启，等价于 `OPENCLAW_PERMISSION_MODE=full_control`，并对每个任务再次确认。

操作记录：
- 每次读取、写入、导入、规划、投影、桌面请求、权限阻止都写入 audit JSONL。
- 企业版提供审计检索、导出、保留周期、哈希校验和管理员策略。

企业部署：
- 离线优先部署，本地模型和工具包由管理员签名更新。
- allowed roots 由 MDM/管理后台下发。
- 日志本地保存，可选同步到企业 SIEM。
- 云 ASR/LLM/TTS 作为禁用默认项，只有策略允许并提示数据边界时才启用。

## 8. 四大应用场景闭环

### 8.1 会议闭环

| 环节 | 设计 |
| --- | --- |
| 触发方式 | 用户说“开启会议模式”，或日程/环境事件提示后由用户确认开启 |
| 系统理解 | 识别会议标题、参与者、当前议题、转写文本、决策和行动项 |
| AI执行 | 生成纪要、行动项、责任人、截止时间、邮件草稿和提醒 |
| 用户确认 | 投影“会后确认”卡片，参会者确认或口头修正 |
| 输出结果 | 纪要 markdown、transcript JSON、follow-up email draft、reminders |
| 保存或导出 | 保存到 workspace；可导出 PDF/Markdown/邮件草稿，企业版入档 |

### 8.2 文档闭环

| 环节 | 设计 |
| --- | --- |
| 触发方式 | 用户拖入/导入文件，或说“分析这份合同/对比两个版本” |
| 系统理解 | 检查文件是否在 workspace/allowed roots，识别文档类型和目标任务 |
| AI执行 | 摘要、风险点、条款提取、版本对比、报告提纲 |
| 用户确认 | 投影或前台语音展示关键结论和不确定点，要求用户确认引用范围 |
| 输出结果 | 摘要、对比报告、条款清单、报告提纲 |
| 保存或导出 | 写入 workspace，带来源文件名、sha256、生成时间和审计记录 |

### 8.3 代办闭环

| 环节 | 设计 |
| --- | --- |
| 触发方式 | 会议行动项、语音提醒、日历冲突、文档中的待办语句 |
| 系统理解 | 抽取事项、责任人、截止时间、优先级和上下文文件 |
| AI执行 | 创建本地提醒/日程，检测冲突，生成跟进草稿 |
| 用户确认 | 前台提示“是否创建这些提醒”，投影行动项勾选卡 |
| 输出结果 | 本地 reminders、agenda、冲突提示、跟进邮件草稿 |
| 保存或导出 | 保存本地日程/提醒库；企业版同步到 Outlook/企业日历需授权 |

### 8.4 桌面协同闭环

| 环节 | 设计 |
| --- | --- |
| 触发方式 | 用户说“打开这份文件/查找合同/打开网页/帮我整理桌面流程” |
| 系统理解 | 区分安全动作与全权桌面操作，判断是否需要 full_control |
| AI执行 | 安全动作只在 allowed roots/确定命令内执行；全权操作先生成计划 |
| 用户确认 | 高风险动作、GUI 自动化、发送/删除/提交必须二次确认 |
| 输出结果 | 打开应用/URL/授权文件，或生成可审计桌面 workflow plan |
| 保存或导出 | 记录到 audit log；流程计划保存到 workspace；企业版可回放审计 |

## 9. 硬件方案

推荐方向：底座投影。

理由：
- 投影亮度和散热是首代落地的主风险，底座更容易容纳光机、散热器、低噪风扇和主算力。
- 球形/头部内置投影会增加头部重量，影响舵机寿命和动作稳定，并把风扇噪音带到麦克风附近。
- 底座投影更适合连续会议、企业维护、成本分层和量产测试。

取舍：
- 牺牲部分“灯头即投影”的视觉魔法。
- 通过头部动作/灯光与底座投影同步补偿，例如灯头看向用户，底座投出确认卡。

硬件配置建议：
- MVP：外接显示器/HDMI 显示输出 + 本地主机/Jetson 开发板 + LeLamp 头部摄像头/音频/状态灯，用显示器临时代替投影面。
- P1：底座微投光机或外置光机样机，验证 20-40 英寸办公卡片可读性。
- P2：底座集成 600-1000 ANSI 级别目标光机样机，验证中等环境光办公卡片。
- 企业版：外接显示/会议室投影接口、物理隐私开关、硬件网络开关、审计导出口。

不承诺：
- 首代不替代会议室主投影。
- 首代不保证明亮有窗会议室下大屏文字可读。
- 未实测前不承诺球形内置投影。

## 10. 技术难点

1. 硬件集成：投影、摄像头、麦克风、散热、舵机、主算力、电源和外壳空间互相制约。
2. OpenClaw 办公场景优化：Skill 边界、任务拆解、状态恢复、失败回滚、人工确认都要工程化。
3. 多模态融合：音频、摄像头、屏幕、投影和文件上下文容易冲突，需要统一事件模型。
4. 安全隔离：必须把 workspace、allowed roots、桌面 backend、full_control 和日志策略产品化。
5. 低延迟：唤醒、ASR、规划、OCR、LLM、TTS、投影渲染需要分段测量。
6. 人机交互：用户必须知道设备何时在听、看、执行、被阻止和等待授权。
7. 稳定性：长会议、热降级、麦克风噪音、投影遮挡、OCR 后端缺失都要有降级路径。
8. 工程落地：样机能力要能转成可维护 BOM、产测流程和企业部署策略。

## 11. 风险分析

| 风险 | 严重性 | 证据/原因 | 缓解 |
| --- | --- | --- | --- |
| 投影亮度不足 | 高 | 办公环境光要求高，小型光机受限 | 限定近距离卡片，底座投影，外接显示降级 |
| 散热和噪音 | 高 | 投影和算力都会发热，风扇影响 ASR | 底座散热、风扇隔离、会议模式降亮 |
| OpenClaw 权限过大 | 高 | 桌面 agent 易受 prompt injection/过度代理影响 | 默认 sandbox、白名单、二次确认、审计 |
| 文件误读/越权 | 高 | 企业资料敏感 | workspace 导入、allowed roots、hash、日志 |
| OCR 不稳定 | 中 | 纸张角度、阴影、表格复杂 | PaddleOCR 接入后用真实样本验证，失败可人工校正 |
| 会议纪要幻觉 | 中 | 转写错误和 LLM 总结可能误判 | 投影现场确认，标记不确定项，保存 transcript |
| 隐私/录音合规 | 高 | 会议录音需告知和同意 | 可见状态灯、开会提示、企业策略、删除机制 |
| 成本失控 | 中 | 光机、NPU、散热、结构都增加 BOM | 分层 SKU，先验证核心闭环 |
| 用户把它当万能 agent | 中 | 过度期待自动操作 | 明确安全边界，默认不发送/删除/购买/支付 |

## 12. MVP 建议

### 12.1 首批功能优先级

P0 必做：
- 会议 transcript 导入或会议模式转写。
- 纪要、决策、行动项、邮件草稿、提醒、投影确认。
- workspace 文件导入、allowed roots 搜索、文档摘要/对比。
- 投影确认卡、倒计时卡、状态卡。
- 外接显示器全屏预览，临时代替投影输出。
- 安全状态页：当前模式、workspace、allowed roots、audit log、desktop backend。
- 桌面安全动作 audit_only + local backend 演示：打开 URL、打开允许文件、查找文件、音量/媒体。

P1 验证：
- PaddleOCR 实体文档扫描。
- 屏幕截图 + OCR 摘要。
- 本地 ASR/VAD 和说话人分离。
- 真实投影光机接入、投影校准、遮挡检测、环境光提示。

P2 暂缓：
- 全自主 GUI 点击。
- 自动发送邮件/提交表单。
- 手机短信/电话桥接。
- 球形结构内置投影。

### 12.2 验证指标

| 指标 | MVP 目标 |
| --- | --- |
| 会议闭环完成率 | 给定 transcript 能生成纪要、行动项、邮件草稿、提醒、投影确认 |
| 行动项确认效率 | 会议结束 3 分钟内完成投影确认和导出 |
| 文件越权测试 | 未授权目录读取全部被阻止并写 audit |
| 桌面执行安全 | 默认 audit_only 不改变系统状态 |
| 显示输出可读性 | 外接显示器全屏卡片在会议确认距离内中文可读；真实投影可读性进入 P1/P2 验证 |
| OCR 初测 | A4 打印文档、名片、表格分别给出识别结果和置信问题 |
| 延迟 | 唤醒到反馈、会议摘要、投影渲染分别记录 P50/P95 |
| 审计覆盖率 | 文件/投影/桌面/权限阻止/会议模式关键动作 100% 有日志 |

### 12.3 演示路径

1. 小爱唤醒：设备亮起并进入 listening。
2. 用户开启会议模式，投影显示“会议记录中”。
3. 导入一段会议 transcript 或现场录一小段。
4. OpenClaw 生成纪要、决策、行动项。
5. 投影行动项确认卡，用户口头修改一项负责人。
6. OpenClaw 写入纪要、transcript、邮件草稿和提醒。
7. 用户要求“找一下 liability termination”，OpenClaw 只搜索 allowed roots。
8. 用户要求打开未授权路径文件，系统拒绝并展示安全边界。
9. 用户查看审计日志，确认所有动作可追踪。

### 12.4 后续迭代路线

第 1 阶段：可演示闭环

- LangGraph/状态机式长任务。
- 沙箱 GUI 自动化。
- 技能市场/企业技能包。
- 多设备会议室协同。
